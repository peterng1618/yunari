# System Tray Host Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the Yunari host hidden at sign-in with a tray icon that opens the editor's existing surfaces, pairs a display, reports and starts installed external programs, and exits the host.

**Architecture:** The tray is a view over the existing host process, never a second server. A platform-neutral menu model and controller own polling, notices and actions; a PowerShell WinForms adapter serves Windows and a staged `systray2` Linux binary serves Linux. The editor modes are reached by `?mode=`/`?publish=1` on the existing page, not by a new route.

**Tech Stack:** TypeScript 7, Node 22+, Vite, Vitest, PowerShell 5.1 WinForms, `systray2@2.1.4` Linux binary, Playwright.

**Spec:** [`docs/superpowers/specs/2026-10-25-systray-design.md`](../specs/2026-10-25-systray-design.md)

## Global Constraints

- Windows and Linux only. `--tray` on macOS, or on Linux without `DISPLAY`/`WAYLAND_DISPLAY`, fails with one clear sentence.
- No new npm runtime dependency. The Linux tray binary is staged by `packages/host/scripts/vendor-tray.mjs` from the pinned `systray2@2.1.4` tarball, SHA-256 `24a176933952c4db79026dcec25c7acf48e5c1cee5d94bc6b87740060bc8ed00`, and is x86-64 only.
- `--tray` implies no browser. A sign-in entry starts the same host with `--tray -n`, hidden.
- LHM and RTSS rows exist only when the program is installed or running. RTSS starts only on an explicit click; never auto-start, inject, hook, or stop it on Exit. Now Playing has no tray row and `MediaProvider` is untouched.
- Keep files under 500 lines where practical; 800 is a stop for normal source files.
- `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` are on. Never coerce invalid numbers to zero.
- Run `npm install` from `src/web/` once before Task 1; this worktree was fast-forwarded over a merge.
- Each task ends with its own commit. Before each commit, replace `STATUS.md`'s "Last completed change" with a 1–5 bullet summary of that commit, one item per line, and run `npm run status:check` from `src/web/`.
- Do not edit plugins, skills, hooks, MCP servers or Claude settings.
- No scratch files in the repo. Temp proofs use `os.tmpdir()`.

## Review Focus

1. **Nothing installed.** A machine with neither LHM nor RTSS must show no external-program rows and no placeholder; a failed process or HTTP probe reads as absent, not as a stopped row.
2. **Unsupported or headless `--tray`.** macOS and Linux with no graphical session must exit visibly, never run an invisible host with no Exit path.
3. **Autostart duplication and quoting.** A legacy `YunariHost` task plus the new hidden entry must read as one enabled state and disable both; node paths, app folders and user names with spaces or quotes must not corrupt the VBS or `.desktop` command.
4. **Tray death and ownership.** If the tray process dies, the host stops; Exit stops LHM only if this run started it and never stops RTSS.
5. **Deep links over existing state.** `?mode=` and `?publish=1` must not destroy an open document, must ignore unknown modes, and `publish=1` must do nothing in a non-editor mode.

- [ ] **Step 3: Implement `external-apps.ts`**

- Platform gate: `platform` defaults to `process.platform`. On anything but `win32`, both states are `{installed:false,running:false}`, `find*Executable()` returns `undefined`, and both starts return `{ok:false,message:"… is available on Windows only."}`. Both programs are Windows-only in this design.
- Paths: LHM checks the explicit `--lhm-exe`, `lhmDefaultExecutable`, then `C:\Program Files\LibreHardwareMonitor\LibreHardwareMonitor.exe` and `C:\Program Files (x86)\...`. RTSS checks `--rtss-exe`, then `C:\Program Files (x86)\RivaTuner Statistics Server\RTSS.exe` and `C:\Program Files\...`.
- `lhmState`: `fetchImpl(`${lhmUrl}/data.json`, { signal: AbortSignal.timeout(1000) })`; `running = httpOk || process`; `installed = executable !== undefined || httpOk || process`; `detail = process && !httpOk ? "web server off" : undefined`.
- `rtssState`: `running = process`, `installed = executable !== undefined || process`.
- Default process probe uses `tasklist` with `/FI IMAGENAME eq <image>`, `/FO CSV`, `/NH`, a 3 s timeout, `windowsHide: true`; any error or non-Windows platform returns `false`.
- `startLhm`: if `ownedStop` exists return `{ok:true,message:"LibreHardwareMonitor is already starting."}`; if the web server answers return already running; if the process runs without the server return the `web server is off` failure; if no executable return a clear failure; otherwise call `launchLhm` with a 20 000 ms timeout, keep its `stop`, and return `{ok, message, started, reason}`. Foreground uses `started`/`reason` for the existing banner; tray mode ignores the message.
- `startRtss`: if running or no executable, return the matching message; otherwise spawn detached, resolve `{ok:true}` on `spawn` and `{ok:false}` on `error`; call `unref`.
- `startLhm` and `startRtss` always resolve an `ActionResult`; a failed spawn or a rejected launch is caught and returned as `{ok:false,message}` rather than escaping as an unhandled rejection from the tray's background start.
- `stopOwnedLhm` sets a `stopping` flag and calls the stored stop; a launch that resolves after the flag is set is stopped immediately. There is no RTSS stop.

- [ ] **Step 3: Implement `host-autostart.ts`**

- Windows path: `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\Yunari.vbs`. VBS body: `Set WshShell = CreateObject("WScript.Shell")` then `WshShell.Run "<command>", 0, False`, where each arg is quoted and internal quotes are doubled. Refuse an arg containing a newline or a double quote (throw; `enable` catches and returns `{ok:false}`), rather than writing an entry that cannot be parsed.
- Legacy task path: `<systemRoot>/System32/Tasks/YunariHost`; state is true when the VBS exists **or** that file exists. Enabling checks the legacy task and deletes it with `schtasks /Delete /TN YunariHost /F` before writing the VBS; a failed deletion returns `{ok:false}` and writes nothing. Disabling deletes it only when that file exists, then removes the VBS. A temp-directory test therefore never runs `schtasks` against the real machine.
- Linux path: `$XDG_CONFIG_HOME/autostart/yunari.desktop`, else `~/.config/autostart/yunari.desktop`. `Exec=` quotes each arg, `Terminal=false`, `X-GNOME-Autostart-enabled=true`.
- macOS returns `{ok:false, message:"Yunari registers start-at-sign-in on Windows and Linux only; this host is on darwin."}`.
- Messages on success: `"Yunari will start hidden at sign-in."` and `"Yunari will not start at sign-in."`.
