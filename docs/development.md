# Development

All npm commands run from `src/web/`. The repository root has no
`package.json`.

## Prerequisites

- **Node** `>=22`; Vitest 5 supports `^22.12`, `^24` and `>=26`. CI pins Node 24.
- **A Chromium browser** for Playwright: `npx playwright install chromium`.
- **Windows** for the host's full sensor and helper-process path. The browser
  and unit suites run on CI's Linux runners.

## First run

```bash
cd src/web
npm install
npm run build
node packages/host/bin/yunari.js
```

`npm run build` builds the workspaces in dependency order. The host shim imports
`packages/host/dist/main.js` and refuses to start without it, so rebuild the host
after changing it. The host opens a browser by default; `--no-browser` keeps it
headless.

## Commands

| Command | What it does |
|---|---|
| `npm run build` | Build every workspace bundle |
| `npm run gate` | Biome check, script self-tests, docs/scratch/third-party/workflow/ffmpeg checks, design checks, typecheck, Vitest, Worker tests |
| `npm test` | Vitest unit suites |
| `npm run typecheck` | Every workspace plus the e2e TypeScript project |
| `npm run test:e2e` | Playwright main config (built bundles + real host) |
| `npm run test:display` | Real host and phone rendering; own config, one worker |
| `npm run test:rebuild` | Reference composition rebuilt by hand; own config, one worker |
| `npm run design:check` | Token ratchet, Google design.md lint, DESIGN.md/CSS sync |
| `npm run docs:check` | Every `plans/…md` reference resolves |
| `npm run size` | Player gzip budget |
| `npm run third-party:check` | Inventory matches installed manifests |
| `npm run audit:check` | Dependency audit policy (needs the registry) |
| `npm run scratch:check` | No scratch outside sanctioned locations |

`npm run gate` is the one command that means green. It is offline; the live
audit is a separate CI job.

## Tests

- **Vitest** collects `packages/*/src/**/*.test.ts(x)` and pure readers under
  `tests/`. `.dom.test.ts(x)` files use jsdom with the `canvas` package for a
  real 2D context.
- **Playwright** collects only `*.spec.ts` under `tests/e2e`. The two runners do
  not collect each other's files.
- Browser tests preview **built** bundles. Run `npm run build` first; `dist/` is
  gitignored, so a fresh checkout has nothing to preview.
- The main config previews the player on `4173`, the editor on `4174`, and boots
  the real host on `HOST_PORT`.
- Ports are fixed with `--strictPort`, and each config or own-host spec owns its
  port. Shared host state runs with `workers: 1`; preview projects keep full
  parallelism.
- `@yunari/store-worker` nests Vitest 4 because
  `@cloudflare/vitest-pool-workers` peers on `^4.1.0`. The workspace runs Vitest
  5. Keep the nested version until the pool supports 5.

## Visual evidence

Captures write PNGs, so run them one at a time:

```bash
YUNARI_CAPTURE=1 npx playwright test --project=desktop-chromium \
  --grep "<capture title>" --workers=1
```

`YUNARI_CAPTURE_DIR` changes the output directory (default
`test-results/captures`). The `visual-evidence` GitHub workflow takes a `grep`
and a `project` input and uploads the PNGs as an artifact.

## Tooling constraints

- **Mechanism changes require reuse evidence.** Before implementing at a
  rendering, persistence, scheduling, hardware, media, security or shared
  lifecycle boundary, complete the seven-rung search in `AGENTS.md`: internal
  owner, installed dependencies, native platform, public solutions, integration
  comparison, smallest probe, then build/reuse. Record it in
  `docs/decisions/NNNN-<slug>.md` with the change. Public searches must inspect
  actual solutions and constraints, not only package names.
- **Driver and protocol tests belong at their seam.** Unit-test packet layouts,
  validation, cadence and failure handling without hardware. Browser-test the
  real rasterized output when panel rendering changes. Claim support for a
  hardware/firmware combination only when that combination was exercised.
- **Vite 8 bundles with Rolldown.** `manualChunks` must be a function; the object
  form fails with `manualChunks is not a function`.
- **The editor uses `base: "./"`.** Its bundle is mounted both at the preview
  root and under the host's `/editor/`; an absolute base would resolve assets
  against the player's `dist` and boot a blank stage.
- **Fabric imports.** Use `fabric/es` and `StaticCanvas` outside the editor. The
  boundary test fails with the measured gzip cost.
- **Generated bytes.** `npm run icons:generate` rewrites the icon sets and
  `npm run fonts:generate` the font trios; commit generated output with the
  source change. Host vendor scripts stage LibreHardwareMonitor, PresentMon and
  the tray helper; vendored binaries are gitignored, weather icons are tracked.
- **Dependencies.** A new runtime dependency needs a `THIRD-PARTY-NOTICES.md`
  entry. `ffmpeg-static`'s downloaded binary is checked against
  `ffmpeg-static-hashes.json`.

## Windows notes

- Use `fileURLToPath(new URL(…, import.meta.url))`, not `URL.pathname`; on
  Windows the latter yields `/D:/…`.
- Resolve entry points through `realpathSync` and compare drive letters
  case-insensitively, so a symlinked or differently-cased invocation still runs.
- `path.relative` yields backslashes on Windows; convert to POSIX before
  emitting paths or comparing them.
- PowerShell treats backticks as escapes. Quote patterns carefully or use the
  Bash tool for regexes containing backticks.

## Scratch

Agent scratch belongs in `src/web/.agent-scratch/` or `/tmp` (drive-root
`C:\tmp` on Windows). `npm run scratch:check` sweeps the tree for residue
elsewhere. Do not commit scratch, coverage, Playwright output or downloaded
binaries.
